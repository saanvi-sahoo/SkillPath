Summary

The Career Advisor is improved by versioned prompts, routing and checks that are tested on fixed question sets, not by retraining model weights. Two team reviews drove this round: the first asked for unseen tests and stricter metrics (E36, prompt v7), the second for intent understanding, evidence chosen per question, claim-level citation checks and a focused prompt with task templates (E37, prompt v8).

How prompt training works here

  • Prompts are versioned files; each new version is compared with the live one on the same questions, model, temperature and retrieval, each question answered by both versions in turn.
  • Objective rules (counts, word limits, labels, 30 days, no invented URLs) are Python checks; citation support is checked claim by claim with an entailment model; usefulness is scored by people (Question Satisfaction Rate, 0/1/2, blinded).
  • A version goes live only if it is better overall and no category is clearly worse. Test sets are frozen before the version they judge exists; ambiguous labels get a written rubric instead of being edited.
  • Every failure gets a root cause first (router, retrieval, grounding, prompt, instruction-following), so the responsible part is fixed.
  • User 👍/👎 is stored as pending; only feedback a teammate approves changes answers.

Failure root causes:

  • v8: prompt × 3, scope_router × 2, retrieval × 1, instruction_following × 1

Decision: v7 stays live; v8 stays the candidate. On the deployed-style model v8 is better overall (all checks 0.95 vs 0.925, no wrongly refused questions, 37% fewer tokens, better claim support), but it lost one of the 8 multi-turn cases (it explained IaaS and SaaS without naming a concrete provider). The acceptance rule says no category may be more than 5 points worse, so v8 is not activated yet. Next: require concrete, named examples in the concept template, test on the development set, and re-check on new unseen cases.

Intent routing (v8): 0.857 → 0.968 on the development set after generalising the rules; on held-out v2 it was 0.68 before the fixes (the clean number) and 0.92 after (no longer unseen). Router fixes for every version: short follow-ups inherit the scope of an in-scope conversation; "what can you help me with?" is a greeting by rule (the hosted router model had started refusing it); without a hosted router model (local/keyless), a weak off-topic vote no longer refuses clear study or career content ("Explain Big-O notation…" was refused in the Mistral run). Locally: 45/45 off-topic cases still refused, 245/247 in-scope allowed.

Scoring corrections applied to every version alike: the refusal detector no longer counts clarifying questions or numbered answers as refusals; the entailment check no longer calls correct absence or count statements about the student's profile ("AutoCAD is not listed in the JD", "you meet 1 of 6") contradictions; those facts are checked by the deterministic profile check instead.

Not run yet.

Citations: checking meaning, not word overlap

An entailment model (NLI) now reads each cited claim against its source and labels it supported, contradicted or insufficient. The review's example is caught: a source listing "Python, SQL" and the answer "The Data Engineer role does not require Python or SQL [S1]" is a contradiction. Only real statements are checked (titles and advice are skipped). Applied to earlier v5/v6 answers, a third of cited claims were stated by their source, half went beyond it, and 3.5% contradicted it; the old word-overlap check had passed 87%.

Next steps

  • Relabel borderline domains in the career dataset; larger candidate pool for career-change queries.
  • Label the 17 real user questions into a new held-out set; approve or reject pending feedback weekly.
  • Activate v8 only if it wins on held-out v2 and on the human QSR.
