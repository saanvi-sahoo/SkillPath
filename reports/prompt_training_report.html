Summary

The Career Advisor is improved by versioned prompts, routing and checks that are tested on fixed question sets, not by retraining model weights. Two team reviews drove this round: the first asked for unseen tests and stricter metrics (E36, prompt v7), the second for intent understanding, evidence chosen per question, claim-level citation checks and a focused prompt with task templates (E37, prompt v8).

E38: real-world reliability (review 3)

The third review asked us to stop chasing prompt scores and make the advisor reliable in messy, real conversations: remember context, find careers for students who are changing field, check evidence honestly, adapt plans, and fail safely. No new prompt version was written (the review advised against v9); the changes are in the pipeline around the prompt and apply to v7 and v8 alike.

  • Conversation state rebuilt every turn: "the second one" → the career it points to, minutes per day, skills the student said they have or lack, corrections, changes of goal, conflicting statements.
  • Structured career search for career changes: background / target / role; search the target, larger candidate pool, exact-title bonus.
  • Adaptive roadmap: per-day status, revision days for hard topics, missed days moved, known topics removed; task completion rate.
  • Failure handling: model down (retrieval-only notice), Atlas down (no invented records), scanned PDF detected, salary/hiring caveats, cross-user records blocked and logged.
  • Deterministic CV/JD check: "you match N of M skills" must equal the stored comparison (an error the citation audit found).
  • Hosted model, 120 realistic cases: v7+e38 better: 0.975 vs 0.933, no category more than 5 points worse.
  • Local Mistral, 50 multi-turn cases: v7+e38 better: 0.62 vs 0.5, no category more than 5 points worse.
  • Keyless, 120 realistic cases: v7+e38 better: 0.425 vs 0.375, no category more than 5 points worse.

How prompt training works here

  • Prompts are versioned files; each new version is compared with the live one on the same questions, model, temperature and retrieval, each question answered by both versions in turn.
  • Objective rules (counts, word limits, labels, 30 days, no invented URLs) are Python checks; citation support is checked claim by claim with an entailment model; usefulness is scored by people (Question Satisfaction Rate, 0/1/2, blinded).
  • A version goes live only if it is better overall and no category is clearly worse. Test sets are frozen before the version they judge exists; ambiguous labels get a written rubric instead of being edited.
  • Every failure gets a root cause first (router, retrieval, grounding, prompt, instruction-following), so the responsible part is fixed.
  • User 👍/👎 is stored as pending; only feedback a teammate approves changes answers.

Citations: checking meaning, not word overlap

An entailment model (NLI) now reads each cited claim against its source and labels it supported, contradicted or insufficient. The review's example is caught: a source listing "Python, SQL" and the answer "The Data Engineer role does not require Python or SQL [S1]" is a contradiction. Only real statements are checked (titles and advice are skipped). Applied to earlier v5/v6 answers, a third of cited claims were stated by their source, half went beyond it, and 3.5% contradicted it; the old word-overlap check had passed 87%.
